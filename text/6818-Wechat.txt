## 项目简介

本项目是一套移动端 + 云端 + 嵌入式硬件的跨平台远程智能交互控制系统，采用分层架构设计：前端为微信小程序交互界面，后端基于 Python Flask 搭建轻量化 Web 服务，底层硬件搭载粤嵌 6818 嵌入式 Linux 开发板。

项目打通了小程序客户端、服务器、嵌入式开发板三者之间的 Socket 网络双向通信链路，用户仅需通过手机微信小程序，即可随时随地远程下发指令，操控远端 6818 开发板完成多媒体播放、系统壁纸自定义更换、音视频文件上传与自动化压缩处理等一系列硬件交互操作，实现了从移动端可视化操作到嵌入式底层硬件执行的完整技术闭环。

## 核心技术栈

前端交互端：微信小程序原生开发，原生 WXML/WXSS 页面布局，按钮交互、网络请求、文件上传能力

后端服务端：Python Flask 框架，搭建本地 Web 接口服务，接收小程序上传的图片、音频、视频文件，配套图像处理、音频压缩、视频处理脚本，自动完成媒体格式适配与压缩，全局消息缓存，实现指令中转、数据持久化

嵌入式硬件端：粤嵌 6818 开发板（Linux C 开发）C 语言 Socket 网络编程，长轮询拉取服务器控制指令，帧缓冲图形显示驱动开发，音视频播放器调用、系统壁纸设置底层驱动，HTTP 协议数据解析、多任务并发处理

## 项目整体流程与设计

### 前端交互端：微信小程序

微信小程序这里，设计了六个界面（home、open_wallpaper、open_video、open_audio、cmd、message）

功能分别为（主页面、设置壁纸、设置视频、播放音频、命令行、消息列表），每个页面包换四个文件.js、.wxml、.wxss、.json

**主页面**：设计一个轮播图，在打开小程序，监听页面第一次加载时发送http请求，从服务器端获取图片，主页面除了设置壁纸、设置视频、播放音频按钮外，还包含一个语音输入按钮，用户长按唤起录音逻辑，在这里，我一开始想的是调用大模型api来转化我的语音，在搜索资料后，我寻找到了更好的方法：微信内置的同声传译插件，引入该插件后，能够直接在小程序端将语音转为文字，再发给服务器。

**设置壁纸界面**：首先在第一次打开该页面时，小程序会发送http请求先获取到服务器端的壁纸数据，在该页面显示出来。点击右下方的加号按钮能够上传任意图片到服务器，然后服务器这里会自动地将图片转码为800*480像素的bmp文件再推送给6818开发板。最顶部壁纸管理点击编辑后，能够选择多图片进行删除操作，进行该操作会同步删除服务器和开发板的对应图片。

**播放视频界面**：监听第一次打开页面后向服务器发送请求获取当前存在的视频http地址，然后将视频显示在页面内，点击右下角选择上传视频，点击删除按钮同步删除数据，点击播放按钮会弹出窗口选择播放时长，选择成功后会向服务器发送播放视频的http和播放时间，服务器再推送给开发板。说明：在这里删除视频逻辑，因为当小程序端正在播放视频时，会一直占用视频资源，这时候点击删除视频服务器无法删除，所以我这里就添加了逻辑，让小程序点击删除视频后先删除掉本地的视频http列表，再刷新页面，将删除请求发送给服务器后服务器启动一个新的线程循环删除该视频。

**播放音频界面**：播放音频这里同理跟上面一样的增加和删除按钮，不同的是在这里的右下角添加了新的录音按钮，点击后弹出窗口能够调用本地录音接口录音，支持录音完成后预览取消发送和确认发送，发送后会自动刷新该页面，显示出新添加的音频。

**消息列表界面**：使用全局列表存储所有的操作，在连接服务器成功、设置壁纸、上传壁纸、删除壁纸等等操作都会显示在这个页面中

**命令行界面**：在打开该页面时，启动一个函数每隔1秒访问一次服务器的专用api，轮询接收开发板的回复消息，在输入命令后发送给服务器，服务器再发送给开发板执行。输入cls执行清屏

**全局报警界面**：在app.js中，存在一个全局的监听函数，通过轮询来监听是否有新的消息，若接收到服务器开发板报警的消息，则会在所有页面顶部弹出一个报警提示，并且将该报警信息和时间存在消息列表中在消息界面显示出来

**注意**：该服务器是使用python flask搭建的http服务器，所以它无法主动发送消息，只能让客户端主动轮询专用api接口来接收消息，这样做实现简单、兼容性强，无需维护长连接与复杂协议，适配Flask同步架构且服务端压力可控；但实时性较差、存在消息延迟，大量无效轮询会浪费服务端资源与网络开销，高并发场景下容易加重服务器负载。

### 后端服务端：python+Flask

后端技术栈：Python + Flask，轻量同步 HTTP 服务，无长连接，全部基于接口响应 + 客户端轮询通信，主要负责中转指令、处理文件、存数据和 AI 交互，是小程序和开发板之间的 “中转站”。

服务一跑起来就绑定 0.0.0.0:5000，开了跨域，统一托管 user_data 里的图片、音频、视频，直接生成 URL 给小程序预览、给开发板读取。

<img src="img/6818-Wechat/flask.png">

**整体流程设计**

**文件接收与自动处理**：小程序上传图片、视频、音频后，后端会自动调用对应的处理脚本，用 ffmpeg 统一转格式、改分辨率：图片转成 800×480 的 bmp，视频压缩适配开发板，音频转成标准 mp3，处理完自动删掉原文件，再把信息写到临时消息里

**指令接收与中转**：小程序发过来的设置壁纸、播放音视频、远程命令、语音控制这些请求，后端收到后解析一下，全都存到 Temporary_Message 临时消息里，等着开发板来轮询取走执行。

**轮询通信模式**：开发板每隔一段时间就请求 /Temporary_message 拿最新指令，执行完再通过 /api/output_cmd 把结果回传给服务器；小程序也靠轮询 /wx_msg 和 /user_alarm 拿命令返回和设备报警，实现两边实时同步。

**文件管理与删除**：做了图片、视频、音频的删除接口，考虑到视频播放时会占住文件删不掉，我加了循环重试逻辑，保证一定能删掉，同时同步通知开发板，保持两边数据一致。

**AI语音指令处理**：集成了大模型 API，配了专属知识库，小程序语音转成文字后，后端直接转成开发板能直接跑的 Linux 命令，再下发给硬件执行。

### 粤嵌6818开发板

开发板这边我用Linux C 语言开发，全程靠多线程并发运行，搭配 Socket 长轮询和服务器通信，负责把小程序下发的指令真正执行到硬件上，是整个项目的执行终端。
开机后先自动配置网卡 IP，完成网络部署，然后同时启动网络通信、系统界面、火焰检测、功能调度四个独立线程，互不干扰稳定运行。

6818开发板这里一共存在13个c文件，主要功能为：

```

//系统——图标主程序
```

**整体流程设计**

**系统初始化与多线程启动**：开发板上电后，先配置 IP，再创建分离线程，分别跑网络通信、系统桌面、火焰检测、功能部署任务，主线程保持运行不退出。

**指令轮询与解析执行**：Socket 线程每隔几秒请求服务器接口，拉取设置壁纸、播放音视频、上传文件、删除文件、远程命令等指令，解析 JSON 拿到操作类型、文件名、播放时长等信息。

**文件自动下载与管理**：收到上传指令后，自动从服务器下载图片、视频、音频到指定目录，支持多线程并发下载；收到删除指令则批量删除本地对应文件，保持和服务器数据一致。

**本地功能与界面交互**：系统线程加载默认壁纸并绘制功能图标，点击可进入本地视频播放、图片浏览、触控画板；画板支持多色彩笔、清屏、退出操作，触控流畅。

**远程命令与结果回传**：接收到远程 Linux 命令后，直接在开发板执行，用 popen 获取输出结果，通过 HTTP 回传给服务器，再同步到小程序显示。

**火焰检测与报警**：检测线程实时读取 ADC 值，发现火焰立刻启动蜂鸣器报警，切换火焰提示图，并向服务器上报错误信息，小程序同步弹出报警提示。

整体采用多线程 + 轮询 + 帧缓冲驱动的设计，指令执行稳定、本地交互流畅、远程控制实时，完美承接小程序与服务器的全部操作，完成从云端到硬件的完整控制闭环。
