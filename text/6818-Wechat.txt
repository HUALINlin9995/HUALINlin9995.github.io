## 项目简介

本项目是一套移动端 + 云端 + 嵌入式硬件的跨平台远程智能交互控制系统，采用分层架构设计：前端为微信小程序交互界面，后端基于 Python Flask 搭建轻量化 Web 服务，底层硬件搭载粤嵌 6818 嵌入式 Linux 开发板。

项目打通了小程序客户端、服务器、嵌入式开发板三者之间的 Socket 网络双向通信链路，用户仅需通过手机微信小程序，即可随时随地远程下发指令，操控远端 6818 开发板完成多媒体播放、系统壁纸自定义更换、音视频文件上传与自动化压缩处理等一系列硬件交互操作，实现了从移动端可视化操作到嵌入式底层硬件执行的完整技术闭环。

## 核心技术栈

前端交互端：微信小程序原生开发，原生 WXML/WXSS 页面布局，按钮交互、网络请求、文件上传能力

后端服务端：Python Flask 框架，搭建本地 Web 接口服务，接收小程序上传的图片、音频、视频文件，配套图像处理、音频压缩、视频处理脚本，自动完成媒体格式适配与压缩，全局消息缓存，实现指令中转、数据持久化

嵌入式硬件端：粤嵌 6818 开发板（Linux C 开发）C 语言 Socket 网络编程，长轮询拉取服务器控制指令，帧缓冲图形显示驱动开发，音视频播放器调用、系统壁纸设置底层驱动，HTTP 协议数据解析、多任务并发处理

**主页面**：设计一个轮播图，在打开小程序，监听页面第一次加载时发送http请求，从服务器端获取图片，主页面除了设置壁纸、设置视频、播放音频按钮外，还包含一个语音输入按钮，用户长按唤起录音逻辑，在这里，我一开始想的是调用大模型api来转化我的语音，在搜索资料后，我寻找到了更好的方法：微信内置的同声传译插件，引入该插件后，能够直接在小程序端将语音转为文字，再发给服务器。

**设置壁纸界面**：首先在第一次打开该页面时，小程序会发送http请求先获取到服务器端的壁纸数据，在该页面显示出来。点击右下方的加号按钮能够上传任意图片到服务器，然后服务器这里会自动地将图片转码为800*480像素的bmp文件再推送给6818开发板。最顶部壁纸管理点击编辑后，能够选择多图片进行删除操作，进行该操作会同步删除服务器和开发板的对应图片。

**播放视频界面**：监听第一次打开页面后向服务器发送请求获取当前存在的视频http地址，然后将视频显示在页面内，点击右下角选择上传视频，点击删除按钮同步删除数据，点击播放按钮会弹出窗口选择播放时长，选择成功后会向服务器发送播放视频的http和播放时间，服务器再推送给开发板。说明：在这里删除视频逻辑，因为当小程序端正在播放视频时，会一直占用视频资源，这时候点击删除视频服务器无法删除，所以我这里就添加了逻辑，让小程序点击删除视频后先删除掉本地的视频http列表，再刷新页面，将删除请求发送给服务器后服务器启动一个新的线程循环删除该视频。

**播放音频界面**：播放音频这里同理跟上面一样的增加和删除按钮，不同的是在这里的右下角添加了新的录音按钮，点击后弹出窗口能够调用本地录音接口录音，支持录音完成后预览取消发送和确认发送，发送后会自动刷新该页面，显示出新添加的音频。

**消息列表界面**：使用全局列表存储所有的操作，在连接服务器成功、设置壁纸、上传壁纸、删除壁纸等等操作都会显示在这个页面中

**命令行界面**：在打开该页面时，启动一个函数每隔1秒访问一次服务器的专用api，轮询接收开发板的回复消息，在输入命令后发送给服务器，服务器再发送给开发板执行。输入cls执行清屏

**全局报警界面**：在app.js中，存在一个全局的监听函数，通过轮询来监听是否有新的消息，若接收到服务器开发板报警的消息，则会在所有页面顶部弹出一个报警提示，并且将该报警信息和时间存在消息列表中在消息界面显示出来

**注意**：该服务器是使用python flask搭建的http服务器，所以它无法主动发送消息，只能让客户端主动轮询专用api接口来接收消息，这样做实现简单、兼容性强，无需维护长连接与复杂协议，适配Flask同步架构且服务端压力可控；但实时性较差、存在消息延迟，大量无效轮询会浪费服务端资源与网络开销，高并发场景下容易加重服务器负载。

### 后端服务端：python+Flask

后端技术栈：Python + Flask，轻量同步 HTTP 服务，无长连接，全部基于接口响应 + 客户端轮询通信，主要负责中转指令、处理文件、存数据和 AI 交互，是小程序和开发板之间的 “中转站”。

服务一跑起来就绑定 0.0.0.0:5000，开了跨域，统一托管 user_data 里的图片、音频、视频，直接生成 URL 给小程序预览、给开发板读取。

<img src="img/6818-Wechat/flask.png">

**整体流程设计**

**文件接收与自动处理**：小程序上传图片、视频、音频后，后端会自动调用对应的处理脚本，用 ffmpeg 统一转格式、改分辨率：图片转成 800×480 的 bmp，视频压缩适配开发板，音频转成标准 mp3，处理完自动删掉原文件，再把信息写到临时消息里

**指令接收与中转**：小程序发过来的设置壁纸、播放音视频、远程命令、语音控制这些请求，后端收到后解析一下，全都存到 Temporary_Message 临时消息里，等着开发板来轮询取走执行。

**轮询通信模式**：开发板每隔一段时间就请求 /Temporary_message 拿最新指令，执行完再通过 /api/output_cmd 把结果回传给服务器；小程序也靠轮询 /wx_msg 和 /user_alarm 拿命令返回和设备报警，实现两边实时同步。

**文件管理与删除**：做了图片、视频、音频的删除接口，考虑到视频播放时会占住文件删不掉，我加了循环重试逻辑，保证一定能删掉，同时同步通知开发板，保持两边数据一致。

**AI语音指令处理**：集成了大模型 API，配了专属知识库，小程序语音转成文字后，后端直接转成开发板能直接跑的 Linux 命令，再下发给硬件执行。

### 粤嵌6818开发板

开发板这边我用Linux C 语言开发，全程靠多线程并发运行，搭配 Socket 长轮询和服务器通信，负责把小程序下发的指令真正执行到硬件上，是整个项目的执行终端。
开机后先自动配置网卡 IP，完成网络部署，然后同时启动网络通信、系统界面、火焰检测、功能调度四个独立线程，互不干扰稳定运行。

6818开发板这里一共存在13个c文件，主要功能为：

```
//客户端主程序

//系统——图标主程序

//系统——获取坐标函数

//系统——绘制图标函数

//客户端——执行远程命令函数
int cmd_main(const char* command);
//系统——画板主程序
int huaban_main();
//加载壁纸函数

```

**整体流程设计**

**系统初始化与多线程启动**：开发板上电后，先配置 IP，再创建分离线程，分别跑网络通信、系统桌面、火焰检测、功能部署任务，主线程保持运行不退出。

**指令轮询与解析执行**：Socket 线程每隔几秒请求服务器接口，拉取设置壁纸、播放音视频、上传文件、删除文件、远程命令等指令，解析 JSON 拿到操作类型、文件名、播放时长等信息。

**文件自动下载与管理**：收到上传指令后，自动从服务器下载图片、视频、音频到指定目录，支持多线程并发下载；收到删除指令则批量删除本地对应文件，保持和服务器数据一致。

**本地功能与界面交互**：系统线程加载默认壁纸并绘制功能图标，点击可进入本地视频播放、图片浏览、触控画板；画板支持多色彩笔、清屏、退出操作，触控流畅。

**远程命令与结果回传**：接收到远程 Linux 命令后，直接在开发板执行，用 popen 获取输出结果，通过 HTTP 回传给服务器，再同步到小程序显示。

**火焰检测与报警**：检测线程实时读取 ADC 值，发现火焰立刻启动蜂鸣器报警，切换火焰提示图，并向服务器上报错误信息，小程序同步弹出报警提示。

整体采用多线程 + 轮询 + 帧缓冲驱动的设计，指令执行稳定、本地交互流畅、远程控制实时，完美承接小程序与服务器的全部操作，完成从云端到硬件的完整控制闭环。

## 详细技术实现

### 6818开发板

开发板程序基于 Linux C 语言及多线程架构开发，开机后自动完成网络初始化，进而创建四个分离线程并行处理网络通信、桌面系统、火焰检测及功能调度任务，主线程维持系统常驻。以下详述各模块的技术实现。

**多线程启动与系统初始化**

在 main 函数中，使用 pthread_create 配合 PTHREAD_CREATE_DETACHED 属性一次性创建 deploy、socket、xitong、jiance 四个线程。分离属性使线程结束后自动回收资源，避免内存泄漏。主线程进入无限 sleep 循环，保证进程不退出。

```
pthread_attr_t attr;
pthread_attr_init(&attr);
pthread_attr_setdetachstate(&attr, PTHREAD_CREATE_DETACHED);
pthread_create(&tid_deploy, &attr, deploy_thread, NULL);
pthread_create(&tid_socket, &attr, socket_thread, NULL);
pthread_create(&tid_xitong, &attr, xitong_thread, NULL);
pthread_create(&tid_jiance, &attr, jiance_thread, NULL);
```

deploy 线程 最先执行网络部署，通过 system 调用系统命令 ifconfig eth0 192.168.1.101 netmask 255.255.255.0，将开发板 IP 固定为 192.168.1.101，为后续与服务器通信奠定基础。

**网络通信与指令轮询**

socket_main 是客户端核心循环。采用 短连接 + 轮询 方式与服务器交互：每隔 3 秒主动向服务器 Temporary_message 接口发起 HTTP GET 请求，拉取最新 JSON 指令，解析后执行对应操作。

```
snprintf(http_request, sizeof(http_request),
    "GET /Temporary_message HTTP/1.1\r\n"
    "Host: %s\r\n"
    "Connection: close\r\n\r\n",
    SERVER_IP);
send(sockfd, http_request, strlen(http_request), 0);
```

收到 JSON 数据后，通过以下自定义解析函数提取字段：

get_msg 提取 msg 字段，区分指令类型（如 add_img、cmd、set_wallpaper 等）。

get_url 提取远程资源路径或命令内容。

get_time 提取时间参数，用于视频定时播放。

get_name_array 提取待删除的文件名列表。

文件下载 采用多线程并发控制。函数 submit_download_task 使用 POSIX 信号量 g_sem 限制同时运行的最大下载线程数。每当有下载任务时，先 sem_wait 获取许可，再封装 DownloadTask 结构体并创建新线程执行 download_file。线程内通过 HTTP GET 从服务器下载文件并写入本地存放路径（图片 → IMG_SAVE_PATH，视频 → MOVIE_SAVE_PATH，音频 → AUDIO_SAVE_PATH）。任务完成后 sem_post 释放资源。

文件删除 delete_files 根据服务器下发的文件名列表，拼接绝对路径后调用 remove 删除本地文件，实现服务器与开发板数据的同步。

远程命令执行 当 msg 为 cmd 时，将 url 字段内容传递给 cmd_main 函数。该函数先对命令字符串做换行符清理，随后区分如下情况：

mplayer 命令：通过 fork 创建子进程，子进程重定向标准输出和错误输出到 /dev/null，再使用 execl("/bin/sh", "sh", "-c", m, NULL) 执行，主进程立即返回并告知服务器“成功播放”。

cd 命令：直接调用 chdir 切换进程工作目录，并将结果通过 http_send 回传服务器。

普通命令：使用 popen(m, "r") 获取管道，逐行读取命令输出并拼接到结果缓冲区，pclose 后通过 http_send 将输出回传给服务器，小程序终端即可实时看到执行结果。

结果回传函数 http_send 将执行结果封装为 {"data":"..."} 的 JSON 字符串，通过 HTTP POST 请求发送到服务器的 /api/output_cmd/ 接口。函数内部使用 json_escape 对包含双引号、换行等特殊字符的数据进行转义，保证 JSON 合法性。

**帧缓冲图形系统**

所有本地图形界面均基于 Linux 帧缓冲（/dev/fb0）构建。tubiao.c 封装了底层操作。

初始化 fb_init 通过 ioctl 获取屏幕信息（800×480，32位色），计算 line_length 后用 mmap 将显存映射到用户空间的 fb_mem 指针上，后续所有绘制均直接修改这段内存。

```
fb_mem = mmap(NULL, line_length * screen_height, PROT_READ | PROT_WRITE, MAP_SHARED, fb_fd, 0);
```

BMP 图片绘制 draw_bmp 读取 24 位无压缩 BMP 文件，解析文件头和信息头获取图像宽高，计算每行字节数（4字节对齐）。读取像素数据后，按从下到上、从左到右的顺序将 BGR 数据转换写入帧缓冲（fb_mem + y * line_length + x * 4），Alpha 通道固定为 0xFF（不透明）。

墙纸与图标渲染 wallpaper_main 直接调用 draw_bmp 全屏显示一张 BMP 壁纸。tubiao_main 在屏幕指定区域绘制多个功能图标（视频、图片、画板、关机、重启），而 tubiao_huaban 则为画板应用绘制颜色选择、清屏和退出工具栏。所有绘制完成后的数据立即通过 msync 同步到显存，保证画面实时刷新。

**系统桌面与本地功能**

xitong_main 线程初始化触摸屏设备 /dev/input/event0，载入默认壁纸并绘制图标，随后进入主循环等待触摸点击。

触摸坐标获取 get_pos 函数循环读取 input_event，累计 ABS_X、ABS_Y 坐标值，直到检测到 BTN_TOUCH 抬起事件，返回触摸点坐标（范围 0~1023，对应 800×480 屏幕需进行换算）。系统根据触摸坐标执行分支：

视频播放：调用 shiping_main，在 /movie 目录下获取所有视频文件，使用 mplayer -loop 0 循环播放，触摸左右屏幕区域切换上/下一个视频，点击退出按钮 kill mplayer 并重新初始化帧缓冲，最后恢复桌面。

图片浏览：调用 tupian_main，遍历 /img 目录下所有图片，左右箭头翻页，可设置当前图片为桌面壁纸（赋值全局变量 WALLPAPER_NAME），退出后桌面自动刷新为新壁纸。

画板：调用 huaban_main，基于帧缓冲实现触控绘图（见下一小节）。

关机/重启：直接执行 system("poweroff") 或 system("reboot")。

**触控画板实现**

huaban_main 是独立图形应用，其核心思路：在触摸按下状态（flag == 1）下，实时转换触摸坐标到屏幕坐标，并在该坐标处绘制半径 10 像素的实心圆（颜色由工具栏选择）。工具栏判断复用触摸坐标：当 sx 处于左侧 64 像素内时，根据 sy 匹配各颜色按钮或清屏、退出按钮。颜色设置仅修改全局变量 pen_color；清屏则遍历全部像素填充背景色，再重新绘制工具栏图标。手写过程中每次画点后均调用 msync 强制刷新，保障笔迹流畅。

**火焰检测与报警联动**

jc_main 线程通过读取 ADC 设备文件 /sys/bus/iio/devices/iio:device0/in_voltage0_raw 实现传感器数值采集。当读取的 ADC 值低于阈值 330 时判定为“检测到火焰”：

调用 bj_main(1) 打开蜂鸣器（/dev/beep 设备，ioctl 控制）；

通过 http_send(SERVER_IP, PORT, "error") 向服务器上报报警信息，服务器转发至小程序全局提示；

调用 wallpaper_main 显示火焰报警图片；

标记全局变量 is_tupian = true。

当火焰消失（ADC 值恢复正常），关闭蜂鸣器，若之前显示过报警图片则恢复为正常壁纸并重绘图标，保证桌面状态复原。检测周期为每秒一次。

**媒体播放控制（远程触发）**

除本地浏览外，开发板支持服务器远程指令控制媒体播放，主要在 socket_main 中处理：

即时播放：msg == "set_movie" 且 mode == "once" 时，直接拼接 mplayer 命令并 system 调用，播放完毕后系统自动回到桌面。

定时播放：mode == "hours" 时，解析 time 字段得到分钟数，换算为秒后调用 movie_main(full_path, play_seconds)。该函数创建新线程，在新线程内 fork 出 mplayer 进程，并 sleep 指定时长后 kill 进程，最后恢复壁纸和图标。

音频播放：通过 madplay 命令播放指定音频文件，同样由 system 直接调用。

以上模块紧密协作，构成了从网络指令接收、本地图形交互、外设检测到多媒体控制的完整嵌入式控制闭环。

### 后端服务端

后端基于 Python Flask 搭建轻量同步 HTTP 服务，绑定 0.0.0.0:5000，开启跨域支持（flask_cors），统一托管 user_data 目录下的图片、音频、视频文件，为小程序提供预览 URL，为开发板提供文件下载地址。以下详细描述各模块实现。

**服务初始化与路由规划**

Flask 应用实例化时指定 static_folder='.'，便于直接通过 URL 提供静态资源。全局定义 Temporary_Message 字典作为开发板指令缓存，wx_Message 字典作为小程序消息缓存，is_error 字符串标记报警状态，三者共同实现指令中转与状态同步。

```
app = Flask(__name__,static_folder='.')
CORS(app)
Temporary_Message={"operation":"","url":"","name":[],"mode":"","time":""}
wx_Message={"msg":""}
is_error="正常"
```

路由设计覆盖三大类：资源获取类 (/user_data/<path:filepath> 等)、数据修改类 (/delete/*、/api/upload 等)、监听与中转类 (/Temporary_message、/wx_msg、/user_alarm 等)。所有业务逻辑均围绕这几个全局变量展开。

**文件上传与自动处理**

三个上传接口 /api/upload、/api/mp4、/api/audio 分别接收图片、视频、音频文件，内部统一调用 get_image_list(is_img) 函数。该函数根据 is_img 参数（1=图片，0=视频，2=音频）执行不同处理流程：

图片处理：接收文件先以时间戳命名保存为 .jpg，调用 proess_img.compress_image 将原始图片转换为 800×480 的 BMP 格式，转换成功删除原文件，并将 BMP 文件的 URL 写入 Temporary_Message，标记 operation="add_img"，等待开发板拉取下载。

视频处理：接收文件保存为临时 1.mp4，调用 process_movie.compress_movie 进行分辨率缩放、帧率设置、编码压缩，输出为适配开发板的 MP4 文件（H.264 baseline + AAC），处理后同样删除临时文件，将最终视频 URL 写入 Temporary_Message，标记 operation="add_movie"。

音频处理：接收文件保存为原始格式，若扩展名已是 .mp3 则直接重命名为时间戳文件；否则调用 process_audio.compress_audio 使用 FFmpeg 将音频转为 MP3 格式，最后将 MP3 文件 URL 写入 Temporary_Message，标记 operation="add_audio"。

所有压缩脚本均基于 subprocess.run 调用 FFmpeg 命令行，并捕获异常确保健壮性。

```
# 图片压缩命令示例
cmd = [
    'ffmpeg',
    '-i', input_path,
    '-s', '800x480',
    '-c:v', 'bmp',
    '-y',
    output_path
]
subprocess.run(cmd, check=True, capture_output=True, text=True)
```

**指令中转与临时消息机制**

服务器作为小程序与开发板之间的“中转站”，不主动推送消息，而是通过轮询实现同步。当小程序需要控制开发板时，会请求 /remote/play 接口，传入 msg 类型（wallpaper、movie、audio）及对应参数。服务端从请求 JSON 中提取文件名、播放模式、时长等，重新组装 Temporary_Message 字典：

```
Temporary_Message['url'] = filename
if data['msg'] == 'wallpaper':
    Temporary_Message['operation'] = 'set_wallpaper'
elif data['msg'] == 'movie':
    Temporary_Message['operation'] = 'set_movie'
    Temporary_Message['mode'] = data['playMode']
    Temporary_Message['time'] = data['playTime']
elif data['msg'] == 'audio':
    Temporary_Message['operation'] = 'set_audio'
```

类似的，删除请求 (/delete/img, /delete/movie, /delete/audio) 和命令下发 (/api/input_cmd, /api/audio_AI) 也会将操作类型与参数写入 Temporary_Message，然后等待开发板轮询取走。每个指令消费后，Temporary_Message 会立即清空，避免重复执行。

**客户端轮询与消息同步**

开发板轮询 /Temporary_message：开发板每隔 3 秒访问该接口，服务端返回当前 Temporary_Message 中的 msg、url、name、mode、time 等字段，并在返回后重置字典。若 operation 为 set_movie，额外返回 mode 和 time 字段以便开发板执行定时播放。

小程序轮询 /wx_msg：开发板执行命令后，通过 POST /api/output_cmd/ 将结果回传，服务端将结果存入 wx_Message['msg']。小程序每隔 1 秒轮询 /wx_msg，取走命令执行结果并在终端展示。同样，取走后立即清空 wx_Message。

报警轮询 /user_alarm：当开发板检测到火焰时，会 POST {"data":"error"} 到 /api/output_cmd/，服务端检测到 error 后将全局变量 is_error 设为 '报警'。小程序全局轮询 /user_alarm，若发现状态为报警，则弹出报警提示，并将 is_error 重置为 '正常'。

```
# 回传命令结果处理
@app.route('/api/output_cmd/',methods=['POST'])
def output_cmd():
    global wx_Message, is_error
    data = request.get_json()
    if data['data'] == 'error':
        is_error = '报警'
    wx_Message['msg'] = data['data']
    return jsonify({"code":200,"msg":"收到命令"})
```

**文件删除与同步通知**

删除操作分为两类：图片删除支持批量，视频、音频删除为单个。以图片删除为例，前端发送包含多个 HTTP URL 的列表，服务端遍历提取文件名，逐个调用 os.remove 删除。由于视频文件在客户端预览时可能被占用，删除逻辑加入循环重试：

```
while True:
    try:
        os.remove(file_path)
        break
    except PermissionError:
        time.sleep(0.1)
```

删除完成后，所有被删文件名列表会写入 Temporary_Message，operation 根据类型设为 del_img、del_movie 或 del_audio，开发板轮询到该指令后会同步删除本地对应文件，保证两端数据一致。

**AI 语音命令处理**

语音转文字后，小程序将文本通过 /api/audio_AI 接口发往服务端。服务端调用 call_AI.get_dev_board_command(text) 函数，将用户自然语言转化为开发板可直接执行的 Linux 命令。该函数内部使用 OpenAI 兼容接口调用阿里云通义千问 Qwen-plus 模型，并配置了专属于粤嵌 6818 开发板的知识库提示词：

```
DEV_BOARD_SYSTEM_PROMPT = """

1. 只输出可直接在开发板终端执行的Linux命令，无解释、无多余文字
2. 只能使用我提供的路径，不编造
3. 不知道命令回复：未知命令

"""
```

模型返回的命令字符串会直接作为 cmd 指令写入 Temporary_Message，由开发板拉取执行，实现从语音到硬件控制的完整链路。

以上各模块围绕全局变量 Temporary_Message 进行协作，形成了轻量、解耦、可轮询驱动的后端指令中转架构，完美适配 Flask 同步模式，支撑起小程序与 6818 开发板之间的所有交互逻辑。

**App 全局配置与报警轮询**

app.js 中定义 globalData 统一存放用户信息、全局报警标志 globalShowAlert 和全局操作历史列表 globalList。get_alarm 函数通过 wx.request 轮询 /user_alarm 接口，若服务端返回 msg === '报警'，则将 globalShowAlert 置为 true，同时向 globalList 添加一条带时间戳的报警记录，驱动页面顶部弹出报警提示栏，所有页面均可通过访问全局变量感知报警状态。

```
get_alarm() {
  wx.request({
    url: 'http://127.0.0.1:5000/user_alarm',
    method: 'GET',
    success: (res) => {
      if (res.data.msg === '报警') {
        this.globalData.globalShowAlert = true
        this.globalData.globalList.push(`!${this.showNowTime()} 开发板报警提示`)
      }
    }
  })
}
```
**首页语音识别**

引入微信同声传译插件 WechatSI，使用 getRecordRecognitionManager() 获取全局语音识别管理器。用户长按按钮触发 startRecord 后调用 manager.start({lang: "zh_CN"}) 开始识别，onStop 回调中获取 res.result 即转换后的文本，随后自动调用 send_text 将文本发往后端 /api/audio_AI，由大模型转换为开发板命令。

```
const plugin = requirePlugin("WechatSI")
const manager = plugin.getRecordRecognitionManager()
startRecord() {
  manager.start({ lang: "zh_CN" })
}
onLoad() {
  manager.onStop = (res) => {
    this.setData({ text: res.result })
    this.send_text()
  }
}
```

**远程播放控制**

壁纸设置、视频/音频播放均调用 /remote/play 接口。构造请求体 data 中包含 msg 字段区分操作类型，Url 为资源完整地址。视频额外传递 playMode（'once' 单次 / 'hours' 定时）和 playTime（分钟数），服务器据此组装 Temporary_Message 下发开发板。

```

wx.request({

wx.request({

**命令行交互**

命令页通过 wx.request 将用户输入 POST 至 /api/input_cmd。同时启动一个 2 秒轮询定时器，持续请求 /wx_msg 接口获取开发板回传的命令输出。收到 res.data.msg 不为空时，将其推入 commandHistory 数组并在页面渲染，实现远程终端的实时反馈。输入 cls 可触发本地清屏。

```
input_cmd(options) {
  wx.request({
    url: config.SERVER_IP + '/api/input_cmd',
    method: 'POST',
    data: { cmd: options.detail.value }
  })
}
startTimer() {
  setInterval(() => {
    wx.request({
      url: config.SERVER_IP + '/wx_msg',
      success: (res) => {
        if (res.data.msg) {
          this.data.commandHistory.push({ type: 'server', content: res.data.msg })
        }
      }
    })
  }, 2000)
}
```

**录音与音频上传**

录音页面使用 wx.getRecorderManager() 进行录音，设置最长 60 秒，格式为 aac。录音结束触发 onStop 回调，获取临时文件路径 tempFilePath。用户可预览确认后，通过 wx.uploadFile 将录音文件上传至 /api/audio，后端自动压缩为 MP3 并更新 Temporary_Message，通知开发板磁盘同步。

```
startRecord() {
  wx.getRecorderManager().start({
    duration: 60000,
    format: 'aac'
  })
  wx.getRecorderManager().onStop((res) => {
    this.setData({ recordFilePath: res.tempFilePath })
  })
}

## 项目总结

本项目成功构建了一套从微信小程序到云端服务器再到粤嵌 6818 嵌入式开发板的完整远程智能交互控制系统，打通了“移动端操作—云端处理—硬件执行”的全链路技术闭环。

在技术实现上，项目采用分层的轻量化架构设计：前端微信小程序原生开发，借助微信生态的语音识别插件和原生 API，实现了直观的图片、音视频管理与远程指令下发功能；后端基于 Python Flask 框架，以短连接轮询的方式完成指令中转、文件自动处理与状态同步，避免了复杂的长连接维护，实现了高兼容性与低部署成本；底层开发板采用 Linux C 多线程编程，结合帧缓冲图形显示、Socket 网络通信与外设检测，可靠承接了来自云端的各项控制指令。

项目的主要成果包括：实现了移动端对嵌入式硬件的远程壁纸设置、音视频播放、文件上传与管理、自定义终端命令执行等核心功能；集成了 AI 大模型语音交互能力，支持用户通过自然语言语音指令控制开发板；开发板端额外实现了本地触控交互界面、电子画板以及火焰检测报警联动，增强了系统的实用性与展示性。

在技术亮点方面，项目巧妙地利用轮询机制在 Flask 同步框架下实现了准实时双向通信，规避了传统长连接方案在轻量级服务器上的实现复杂度；同时通过 ffmpeg 统一媒体处理流水线、多线程并发下载控制以及基于帧缓冲的低成本 GUI 方案，在有限硬件资源下保障了系统运行的流畅性与稳定性。

回顾整个开发过程，也存在一些可以进一步优化的方向：当前基于轮询的通信机制虽然实现简单，但在实时性和带宽利用率上存在天然局限，后续可考虑引入 WebSocket 或 MQTT 协议来提升消息推送效率与服务端并发能力；开发板端的本地图形界面目前基于底层帧缓冲手动绘制，后续可移植轻量级 GUI 框架以获得更丰富的交互控件支持；此外，系统在安全性方面（如通信加密、身份验证）也有提升空间，以适应实际部署场景的需求。

总体而言，本项目完整展示了一个物联网远程控制系统的设计与实现过程，从需求分析、技术选型、模块开发到系统联调，涵盖了嵌入式开发、后端服务、前端交互三大技术领域，具有较高的学习价值和工程参考意义。
